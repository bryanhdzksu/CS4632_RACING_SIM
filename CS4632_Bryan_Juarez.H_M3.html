1. Implementation Summary

1.1 Overview

The Stochastic Motorsport Performance Simulator is a custom-built Python simulation that models motorsport race performance using physics-inspired equations, stochastic variability, and Monte Carlo trials. It is written entirely from scratch using only the Python standard library — no external frameworks or simulation engines are used.

The simulator models how vehicle setup, environmental conditions (weather, wetness, visibility), tire compound strategy, and driver behavior interact to produce race outcomes. Each race is simulated as a sequence of track segments (alternating straights and corners), and the Monte Carlo engine repeats each race hundreds of times to produce probabilistic win distributions rather than single deterministic outcomes.

1.3 Scope Changes from Original Proposal

Milestone 2 feedback identified three priorities that reshaped the M3 work plan:

  1. Wetness/tire sensitivity imbalance — M2 results were too binary (98–100% win rates for one driver). M3 addressed this through five physics changes: smoothstep grip blending, traction-limited acceleration, grip-aware braking, a visibility penalty, and a multiplicative driver skill factor. These distribute performance across multiple dimensions instead of tire choice alone.
  2. CSV export was missing — M2 only produced a single sample_results.txt. M3 implements a full DataCollector that writes four files per run (config JSON, timeseries CSV, events CSV, summary JSON) plus a master run_index.json.
  3. Only two drivers/cars were supported — M2 hardcoded car_a/car_b. M3 generalizes to N entrants via an Entrant dataclass, demonstrated with fields of 3, 4, and 6 participants.

Items partially addressed were deprioritized in favor of these three feedback items:

  • Segment transition realism (#22): Braking transitions are now grip-aware, but a full coasting/lift-and-coast phase was descoped. The current model is sufficient for the tire-strategy analysis the simulation targets.
  • Suspension impact (#23): suspension_factor is a configurable per-car parameter scaling tire grip. A multi-parameter suspension model was deferred as the single-factor approach produces meaningful differentiation.
  • Powertrain model (#25): Traction-limited acceleration constrains straight-line performance by tire grip in wet conditions. A full torque-curve/gear-ratio model was descoped because the simulation focuses on tire strategy and environmental sensitivity.

Items deferred to future milestones:

  • Literature-sourced parameters (#30): Current values are calibrated for balanced outcomes. M4 validation will compare against published data.
  • UML updates (#31): Architecture documentation is maintained in the README.
  • Fuel load, pit stops, tire degradation: Out of scope for the current model.
  • Visualization/charting: Planned for the M4 analysis phase.

2.4 Issues Encountered During Runs

  1. M2 sensitivity imbalance: Initial M3 development inherited the M2 problem where one driver won 98–100% of races regardless of conditions. This was resolved through smoothstep grip blending and tightened tire mu values (DRY: 1.04/0.88, INTERMEDIATE: 1.02/0.93, WET: 1.00/0.97).
  2. Car parameter dominance: Early M3 runs showed one car winning 100% because it was superior in every dimension. This was fixed by creating genuine tradeoffs: the Red Bull has high downforce but high drag; the McLaren has low drag but less cornering grip; the Mercedes is balanced with the best brakes.
  3. Drag model simplification: The current model evaluates aerodynamic drag at segment entry speed only (not continuously). This is a known approximation that slightly favors cars entering straights at lower speed. Documented as a limitation for M4 analysis.

4.3 Analysis of Key Trends

Weather sensitivity — tire strategy matters

Comparing Runs 001 (dry), 003 (cloudy), and 002 (wet) for Norris (WET tires):

ConditionWetnessNorris Win%Avg Gap to Leader
Dry0.058.0%+2.48s
Cloudy0.3025.0%+1.26s
Wet0.8033.0%+0.80s

Norris’s WET tires become increasingly competitive as wetness increases, closing the average time gap from 2.48s to 0.80s. This validates the smoothstep grip blending and confirms the M2 sensitivity issue is resolved — outcomes are no longer binary.

Race length amplifies or compresses advantage

LapsRunLeader Win%Spread
100753.0%27% / 53% / 20%
500179.0%13% / 79% / 8%
1000691.5%8% / 91.5% / 0.5%

Over more laps, stochastic variance averages out and the underlying performance gap becomes more deterministic. This is a known property of Monte Carlo simulation and validates the model’s statistical behavior.

Track layout affects competitive balance

TrackSegmentsRunLeader Win%Runner-up Win%
Monaco Analog16 (tight)00886.0%7.5%
Silverstone Analog12 (mixed)00179.0%13.0%
Oval Analog4 (wide)00957.0%39.5%

Tight, complex tracks amplify the downforce advantage (Red Bull, CL=1.58). Simple tracks with wide sweeping corners compress the field because cornering speed differences are smaller at larger radii.

Field size changes the competitive dynamic

In the 3-entrant dry baseline (Run 001), Verstappen wins 79%. In the 6-entrant dry run (Run 004), Leclerc (Ferrari, DRY tires) wins 70%. The larger field introduces new car/driver combinations that shift the competitive balance.

Wrong-strategy penalty (Run 011)

When all entrants use WET tires in dry conditions, the tire variable is eliminated. Win rates (70.5% / 3.5% / 26%) reveal the pure car-plus-driver differentiation: the Red Bull’s higher downforce and Verstappen’s driver skill factor give a clear edge even without a tire advantage.

4.4 Performance Observations

  • All 12 runs complete in under 1 second each; total batch time is approximately 5 seconds.
  • Execution time scales roughly linearly with the number of entrants and trials.
  • The 500-trial run (Run 010) shows stable convergence of win percentages, confirming that 200 trials is sufficient for reliable estimates in most scenarios.
  • The segment-level events CSV for a typical run (200 trials × 5 laps × 3 entrants × 12 segments) produces approximately 36,000 rows — manageable for analysis tools.
